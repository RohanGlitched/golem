Create a feature spec named golem-sim for skeleton/src/sim: loading MuJoCo WASM (@mujoco/mujoco 4.x) identically in Node and browsers (see mujoco-wasm.md), writing a RobotApp's files into the MuJoCo FS, compiling the model once per worker and reusing it, and running one trial: create MjData, seed a PRNG from TrialSpec.seed, app.initState, warm up for app.warmup seconds under the controller, then fire the trigger (record a 'trigger' event in the Trace), apply each PerturbationCall's template.apply every sim step with values from the Scenario, call controller.step at controlDt, record app.signals at control rate into a Trace, optionally record body poses at 30 fps for ghosts (Float32Array of nbody x 7 per frame), stop at warmup + horizon or early when the monitor is already decided (expose an earlyStop hook, e.g. robot fell for an 'always' requirement), evaluate the monitor, delete MjData, and return a TrialResult. Also: a SimContext with name-to-id lookups for bodies, geoms, sites, joints and actuators; helpers for DoubleBuffer out-params (jacobians), geom distance and contact iteration with guaranteed delete(); a tiny inline MJCF test app (falling box / pendulum) so CI does not need robot assets. Requirements must include bit-identical determinism for the same TrialSpec in the same runtime, no allocation inside the step loop, and no handle leaks (every handle deleted, verified by a counter in tests). Property tests: determinism, trace length equals horizon/controlDt, trigger event time equals warmup, early stop never changes a decided verdict.
