Create a feature spec named golem-falsify for skeleton/src/falsify and skeleton/src/pool. Falsification of one CompiledRequirement with a TrialPool (interfaces.md): phase 0 re-runs pinned seeds from .golem/seeds; phase 1 random sampling (Latin hypercube over the ScenarioSpace, wrap-aware for angles and phases); phase 2 cross-entropy method: per-dimension truncated normal (wrapped normal for wrap dims) fitted to the elite fraction (lowest robustness), generations of configurable size, stop at first robustness < 0 or budget exhausted; phase 3 shrinking: from a failing scenario, bisect each severity dimension toward its milder end to find the mildest still-failing value (fixed seed), then re-verify with 3 extra seeds to classify the counterexample as robust or seed-sensitive; output a Verdict with trials per phase, closest call, counterexample, and a 95% upper bound on failure rate from the random phase (rule of three when zero failures, Clopper-Pearson otherwise). Budgets: max trials or wall time. Progress callbacks per generation so the UI can render ghosts generation by generation. TrialPool implementations: in-process (single thread, for tests), Node worker_threads, browser Web Workers (module workers, each loading MuJoCo and the app once), with backpressure, cancellation (AbortSignal) and restart of a crashed worker. Seed database: read/write .golem/seeds/<app>/<reqId>.json, dedupe equal counterexamples. Also a baseline mode 'random-only' with the same budget, used by the evidence benchmark. Property tests on synthetic analytic robustness functions (no physics): shrinker output still fails and is never more severe; LHS covers each stratum exactly once; wrap-aware sampling stays in range; verdict status is broken iff some trial had robustness < 0; same seed gives the same sequence of scenarios.
