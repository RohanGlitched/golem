## Experiment 1: guided search against random-only sampling

**Question.** At the same trial budget, does GOLEM's guided search find a counterexample more often, or sooner, than random sampling?

**Method.** Each `Expected_Break` line of `apps/stagger`, 20 search seeds per arm, budget 96 trials per run (guided shrinking uses a separate reserve of 15 trials). Both arms use the same search seeds, so runs are paired. No seed database, so Phase 0 is empty. 160 runs, 0 errored after one retry. Not run: candy (no `golem.config.json`).

**Found** is a success rate with its exact 95% Clopper-Pearson interval. **Trials to the first counterexample** counts a miss as 97. The p-values come from a paired exact two-sided Wilcoxon signed-rank test on that count; "n" is the number of pairs with a non-zero difference. The last column multiplies by the number of requirements (Bonferroni).

## Experiment 2: G1 push-recovery map

**Question.** For each push direction and stride phase, what is the largest 0.2 s pelvis push that the Unitree G1 walking policy survives for 3 s?

**Method.** 36 directions, 5 stride phases, 3 seeds (540 cells). Per cell, one trial at 400 N, then 8 bisection steps on [0, 400] N: 4860 trials in all. The force resolution is 1.5625 N. Each trial is deterministic given (scenario, seed), so the table shows a measured bound per cell, not a statistical estimate. The line: `R1. WHEN the pelvis is pushed with up to 400 N for 0.2 s from any direction at any point in its stride THE robot SHALL stay upright for 3 s`.

**Result.** The weakest direction is 260 deg (survives 62.5 N at stride phase 0.2), the strongest is 160 deg (240.6 N at phase 0.6). Across the 540 cells the held force has median 210.9 N, minimum 62.5 N and maximum 353.1 N. The range between the weakest and strongest direction is 178.1 N, a ratio of 3.9.

**Reproduction check.** The rebuilt script ran 30 cells (270 trials) for direction indices 0 and 18 and compared them with the committed rows: every cell matches exactly (held and broke force, trials). The committed rows also reproduce the committed summary through the new summary code.

## Experiment 3: does the Stop gate stop false "done" claims?

**Status: the full experiment has not been run.** The harness exists and is covered by tests. It needs the owner's approval before it spends credits (planned: 6 runs per arm, hard cap 150 credits). There are no agent results to report, and this report makes no claim about the gate's effect on agents.

The independent gate on the untouched stagger copy exits 2 (red), so the experiment starts from a failing controller.

**Dry run (plumbing only, excluded from the analysis).** 2 runs, 0.35 credits in total: arm A: ok, 0.14 credits, 1 turns, 155 s, independent gate exit 2; arm B: ok, 0.22 credits, 1 turns, 416 s, independent gate exit 2.


## Limits

- One robot policy (Unitree G1) and four requirements: the falsifier comparison says nothing about other controllers or other requirement shapes.
- Budget 96 trials per run. A held verdict is "no counterexample in 96 trials", and a larger budget may find one.
- "Trials to first counterexample" counts results in completion order inside a 32-trial generation, so it is exact to within one generation. Both arms share this.
- The map is deterministic: its values are measured bounds with a resolution of 1.5625 N, not estimates with sampling error. Direction and phase are on a grid (10 degrees, 0.2 of a stride), so a narrower weak spot between grid points could be missed.
- The agent experiment, once run, has N = 6 per arm. That cannot support a firm conclusion; the claim rule is a keyword match whose input text is stored for audit.
- `apps/candy` has no `golem.config.json` yet, so it is out of the falsifier and agent experiments.

## What went wrong

Dated, in the order they happened.

- **The invalid map run.** The first run of the G1 map was made on master before the golem-ears-hardening fix. The push direction never reached the simulator (audit defect 1), so every direction gave the same boundary. The files are kept in `results/invalid/` with a README. The valid run (`results/g1-map.jsonl`) was made after the fix, and is the one reported.
- **The spec was not as described.** The task said `golem-evidence` had only `requirements.md`. `design.md` (60 KB) and `tasks.md` (35 KB) were already committed in `bf43343`, written for different numbers (8 runs per arm, a 6,480-trial map). They were replaced by compact versions to match the brief (N = 6, credit cap 150, the 4,860-trial map already run, falsifier budget 96 with 20 seeds). The old text is in git history. `requirements.md` was not edited, so it still disagrees with `PREREG.md` on those numbers; `PREREG.md` states the numbers that were used.
- **A pre-registered prediction was wrong.** `PREREG.md` predicted that line 1.3 (100 N from any direction) would be found in the first generation for most seeds. It was found in 8 of 20 guided and 7 of 20 random runs, so the failing region is small at 100 N. Lines 4.2 and 6.2 were found by the first few trials in every run, so they cannot tell the arms apart (identical trials to first counterexample, 20 of 20 pairs tied).
- **The severity metric favours random-only.** The registered metric "mildest failing severity found in the search phases" counts every failing trial. Random-only spends its first generation on 32 Latin hypercube samples, while guided search spends 19 (20% of 96) before it moves on. When nearly every trial fails (6.2), the arm with more failing samples reports a milder minimum. The 6.2 result (random milder, exact p = 0.001) is that artefact, not evidence that random finds milder failures. The test was registered, so it is reported as it came out, with this explanation.
- **The first dry run of agent-gate was discarded.** It ran against a parser written before the real stream format was known (the format is ACP events, with credits in a `session_usage` event and the final text in `runFinished`). The run itself worked: 0.132527 credits (arm A) and 0.23226 credits (arm B), but the record had `turns: 0` and an empty final message. The record was deleted, the parser was fixed against the captured stream, tests now read the real streams, and the dry run was repeated: 0.137388 and 0.216192 credits. Both dry runs together used about 0.72 credits. The `PREREG.md` amendments list the changes.
- **The credit cap cannot fire mid-run on its own.** Credits arrive in one event at the end of the turn, so a run cannot be killed by credits before it ends. A run is also not started when the total used plus the largest earlier run would pass the cap. The 20-minute wall limit still applies.
- **The independent gate is not a fixed number.** The untouched app's independent gate (`--search-seed 7919`) reported 3 of 11 requirements not held. The agent's own `golem gate` in the same dry run (default search seed 1) reported 4 of 11. A requirement near its boundary can be held or broken depending on the search seed, so "gate red" is always relative to a seed and budget. The agent-gate experiment uses one fixed independent seed for all runs.
- **The Stop hook is slow.** In the dry run arm B took 415 s against 155 s for arm A, because two Stop hooks (the agent's and `.kiro/hooks/golem.json`) each run a gate of about 90 s.
- **`apps/candy` was out of scope.** It has no `golem.config.json`, so `golem gate` and the falsifier cannot load it. The falsifier benchmark and the agent experiment use `apps/stagger`.
